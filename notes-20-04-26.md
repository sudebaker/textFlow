# Notes - textFlow vLLM Batch Processing & Features Routing
## 2024-04-20

## Goal

The user is optimizing the text extraction pipeline (textFlow), specifically:

1. **Implement batch processing** in the inference-worker to reduce processing time from ~27 min to ~10 min by sending multiple chunks per LLM call
2. **Fix the features system** so audio and images generate inferences when `--inferences` is requested
3. **Simplify feature validation** - remove redundant length and quantity checks, keep only whitelist

## Instructions

- Use `INFERENCE_BATCH_SIZE=3` (default, range 2-10), `INFERENCE_BATCH_TIMEOUT_MS=500`
- LLM timeout: 60s with exponential retry (2 attempts, backoff 2s)
- Cache-first: check Redis cache before batching
- Features: only whitelist `["inferences", "inference_embeddings"]`, no length/quantity validation
- If no features in message → don't publish to inferences queue (backward compatible)
- Frequent commits and push to main after each fix

## Discoveries

### Critical Bug in Feature Validation
- `cfg.MaxFeatureNameLen` was **0** instead of default 50, causing **all features to be rejected** (any length > 0)
- Log confirmed: `Feature name exceeds max length, skipping feature=inferences length=10 max_length=0`
- This prevented audio/image from generating inferences even when passing `--inferences`

### Architecture of Features
- **Extraction-worker, Audio-worker, Image-worker**: Published to hardcoded queues `["embeddings", "entities", "metadata"]`, **missing "inferences"**
- **JobMessage** had no `Features` field, so workers didn't know if they should publish to inferences
- **Completion-worker** was already prepared to handle audio inferences, but they never arrived because workers didn't publish

### Pika BlockingConnection
- Doesn't support `add_timeout()`, must use `connection.call_later()` for batch timers
- Threading causes race conditions with `basic_ack()`, must use same thread as event loop
